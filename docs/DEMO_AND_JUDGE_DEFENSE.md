# Petra Demo & Judge Defense

This document is for presenting Petra without overclaiming it. It is an **expo runbook**, not evidence that every planned feature is already integrated.

## Demo status gate

Before rehearsing a showcase beat, verify that its owning implementation and local acceptance work has landed. In particular:

- authoritative composed flagship state must come from #37;
- React controls/timeline/runtime binding must come from #42;
- live dish rendering and semantic zoom must come from #6;
- Sources/Assumptions presentation must come from #58;
- browser visual, accessibility, responsiveness, and frame-time acceptance must come from #59.

A demo beat whose prerequisite is still open may remain in this plan, but it must not be presented as already working. Never substitute a scripted animation, hard-coded scientific result, or fake inspector value to make the sequence look complete.

## One-sentence pitch

**Petra is a browser-based Petri-dish sandbox where evolution is generated by a reproducible spatial stochastic model, while the interface makes the model's sources, assumptions, and uncertainty visible.**

## Three claims to establish quickly

1. **The biology is authoritative, not the animation.** The simulator owns state; React/Pixi present it.
2. **Selection is not mutation.** Mutations arise from reviewed reproduction/event opportunities; an antibiotic changes which variants succeed.
3. **The model is inspectable.** Petra distinguishes measured, transferred, calibrated, mechanistic, engineering, and visual-only information instead of flattening them into one confidence badge.

## Why it is not “just an animation”

The intended flagship trajectory is driven by:

- limiting-resource fields and resource-limited growth;
- concentration-dependent ciprofloxacin response;
- stochastic reproduction-linked mutation;
- genotype-specific resistance and relative fitness;
- spatial competition/front access;
- seeded stochasticity and replay.

If the renderer is replaced with plain scientific plots, the authoritative trajectory must be unchanged. Rendering can interpolate and explain state; it cannot decide biology.

## Why it is not “just an LLM wrapper”

The flagship does not require an LLM.

An LLM may later explain an event log using Petra's source library, but:

- it does not choose mutations;
- it does not invent MIC values;
- it does not decide survival;
- it does not calculate authoritative biology.

## Flagship scientific seam to disclose

The flagship is a **composed educational model**, not one experiment reproduced end-to-end.

- Regoes et al. 2004 supplies the reference ciprofloxacin concentration-response shape in an E. coli CAB1 context.
- Marcusson et al. 2009 supplies curated MG1655 genotype MIC and relative-fitness measurements.
- Huseby et al. 2017 informs mutation-supply / mutational-target reasoning.
- Shao et al. 2017 and Baym et al. 2016 motivate spatial nutrient limitation and front-dependent evolutionary behavior.

Petra must surface the cross-study transfer seam rather than describing these data as one measured system.

## 90-second primary demonstration

Use a named, transparently selected seed that gives a clear educational trajectory. The seed may be chosen for legibility; the engine must not contain special-case behavior for it.

### 0–12 s — establish the world

Open the flagship *E. coli / ciprofloxacin* scenario.

Show, if verified and available:
- live dish;
- scenario/run identity and seed;
- nutrient or other active scientific overlay with units;
- population/lineage summary;
- provenance/source affordance.

Say:

“Everything you see is downstream of one reproducible simulation state. The animation explains that state; it does not choose the biology.”

### 12–28 s — growth from resources

Advance simulation time.

Show:
- colony/spatial expansion;
- resource depletion or the relevant local field;
- a local inspector reading supplied by authoritative state.

Say:

“Growth is resource-limited, so local conditions change the growth rate instead of every cell following a scripted animation.”

Do **not** equate animation wall time with biological time.

### 28–50 s — apply ciprofloxacin pressure

Apply the verified ciprofloxacin intervention through the real typed command path.

Show:
- exact intervention parameters;
- timeline entry after authoritative confirmation;
- spatial drug field/legend if available;
- sensitive regions slowing or declining only when produced by simulator state.

Say:

“The drug does not tell the population which mutation to make. Mutations come from reproduction; the environment changes which lineages are favored.”

### 50–68 s — explain selection

If the run contains a relevant resistant lineage/event, show:
- lineage identity/ancestry;
- genotype;
- MIC/response shift and relative fitness where authoritative metadata is available;
- source/assumption details;
- the lineage's state before and after pressure.

Preferred line:

“Selection changed frequency; the drug did not summon a useful mutation.”

If the chosen trajectory does **not** produce the intended event in time, do not inject one. Use a second pre-rehearsed seed or a previously recorded authoritative run identified by its run metadata.

### 68–82 s — prove reproducibility

Replay the same scenario/seed/intervention sequence.

Say:

“Same engine version, scenario, seed, and command sequence reproduce the same stochastic history.”

If fork/compare is verified, branch from the same checkpoint and change only the intervention. Otherwise show same-seed replay first; do not claim counterfactual attribution from two unrelated runs.

### 82–90 s — show scientific honesty

Open Sources/Assumptions or the nearest verified provenance surface.

Say:

“We expose which pieces are measured, transferred, approximated, or calibrated, instead of pretending this is a clinical digital twin.”

## Three-minute extension

After the 90-second path, add only verified modules.

### Counterfactual selection experiment

Preferred:
- fork one authoritative state;
- branch A: no ciprofloxacin;
- branch B: ciprofloxacin;
- preserve the same fork origin and disclose any seed divergence;
- compare lineage frequencies at matched simulation times.

Point: a lineage can pre-exist in both branches while selection changes its frequency.

### Fitness trade-off

Compare a genotype with a documented lower relative fitness against a near-neutral genotype with and without drug pressure.

Point: “more resistant” is not a universal scalar advantage; genotype, environment, resources, space, and timing matter.

### Spatial contingency

Show that front access can alter which lineage expands.

Point: evolutionary outcome depends on spatial opportunity, not just the largest MIC value.

### Optional future modules

Phage, temperature/pH, HGT, or ML acceleration are optional extensions. Do not add them to the expo story until their own science/runtime/validation gates are complete.

## Failure-safe demo behavior

A premium expo demo should fail honestly and recover quickly.

If a renderer effect fails:
- keep the simulation paused;
- switch to the authoritative timeline/plots/inspector if available;
- never replace missing state with decorative fake values.

If a run does not produce the intended lineage event:
- restart with another **pre-selected but non-special-cased** seed;
- or replay a saved authoritative run with its scenario, engine version, seed, and command history visible.

If a Sources panel is unavailable:
- use the bundled project documentation/source list;
- state that the UI integration is incomplete rather than implying provenance is absent.

If the browser becomes slow:
- reduce presentation detail/LOD or render cadence;
- do not change biological tick meaning to make the scene look faster.

## Expected judge questions

### “How realistic is this?”

Petra is a mechanistic educational model rather than a full-cell or clinical digital twin. It models selected population/spatial mechanisms and explicitly labels transferred, calibrated, and approximated seams.

### “Are you simulating every bacterium?”

No. That would be computationally wasteful and would imply precision the model does not have. Petra uses aggregate spatial/lineage state and renders representative bacteria or colony texture. A rendered bacterium is not automatically one simulated cell.

### “How are mutations generated?”

From reviewed reproduction/event opportunities. Rare mutation outcomes are sampled stochastically from those opportunities. Ciprofloxacin affects selection through the modeled environment; it is not an input that directly instructs useful mutations.

### “Where do the resistance numbers come from?”

The flagship composes multiple evidence sources. Marcusson et al. 2009 provides MG1655 genotype MIC and relative-fitness measurements; Regoes et al. 2004 provides a reference ciprofloxacin pharmacodynamic shape in a different E. coli context; Huseby et al. 2017 informs mutation-supply reasoning. Petra labels that cross-study composition rather than calling it one experiment.

### “Why can’t you just use the Regoes growth rate everywhere?”

Because the resource-limited ecology baseline and the Regoes pharmacodynamic reference are different contexts. Petra keeps that seam explicit rather than silently treating one paper's rate as the universal Monod growth rate.

### “What is AI doing?”

The mechanistic engine remains authoritative. Petra has an explicit future/optional Emulated mode for validated surrogate acceleration, with out-of-domain refusal and fallback to the mechanistic engine. An LLM may help explain sourced results, but it is not biological authority.

### “Why not use a neural network for the whole simulation?”

The core educational value is causal and inspectable. A surrogate is useful only when benchmarked against the mechanistic engine, kept inside a known validation envelope, and refused when inputs are out of domain.

### “Why TypeScript instead of Rust/WASM?”

The current architecture keeps the deterministic simulation in a Web Worker so it is inspectable and fast to iterate. Rust/WASM should be introduced only after profiling identifies a hot kernel where compute savings exceed transfer/interop complexity. The protocol is intentionally narrow enough to allow that later.

### “How do you know the animation did not change the science?”

Simulation state, worker protocol, and rendering are separate authority layers. Renderer/UI code consumes snapshots or issues typed commands; it does not write biological outcomes directly. A renderer swap must leave the same seeded simulation trace unchanged.

### “Can the same experiment be reproduced?”

The target identity is scenario + engine version + seed + ordered interventions. Same identity must reproduce the same deterministic trace; changing the seed gives a different stochastic trajectory.

### “Can it predict which mutation will happen in a real patient?”

No. Petra produces model trajectories under a curated genotype graph and scenario assumptions. It is not a patient treatment simulator, clinical-isolate predictor, or whole-genome evolution oracle.

### “Why does the most resistant lineage not always win?”

Resistance is not the only determinant. Relative growth, resources, spatial access, timing, and stochastic founder effects can matter. The flagship is designed to make those trade-offs visible rather than using a generic “more mutations = stronger” rule.

### “What would make you trust the model more?”

More matched measurements from the same strain, medium, temperature, geometry, and assay; explicit calibration targets; held-out validation fixtures; and repeated comparison of model predictions against independent experimental observations.

## Things to avoid saying

Do not say:
- “This perfectly simulates real bacteria.”
- “This predicts antibiotic treatment.”
- “Every dot is a bacterium.”
- “The AI knows how the bacteria evolve.”
- “The antibiotic makes them mutate.”
- “These exact parameters all come from the same experiment.”
- “The browser animation speed is biological time.”
- “The model is validated” without naming what was validated, on what data, and under what context.

Prefer:
- “mechanistic educational simulator”;
- “literature-backed component model”;
- “transferred/mechanistic composition”;
- “representative visual”;
- “stochastic trajectory”;
- “same run identity is reproducible”;
- “this source test verifies X; it does not establish Y.”

## Demo reliability without cheating

It is legitimate to:
- save and select a seed that produces a clear educational trajectory;
- preload a named scenario;
- accelerate simulation time through the real scheduler;
- use event-focused presentation transitions;
- keep a known-good authoritative replay as a fallback.

It is **not** legitimate to:
- special-case that seed;
- spawn a resistant lineage because a demo timer reached a certain wall time;
- make renderer particles cause mutations;
- silently use different rules in demo mode;
- show placeholder inspector values as scientific data;
- call a decorative animation “validation.”

## Offline readiness

The core expo path should run from local/static assets:
- no LLM required;
- no remote model required;
- citations/source metadata bundled;
- no network request required for simulation;
- lockfile/reproducible local install completed before the expo;
- known-good production build tested offline.

No hosted CI is required or allowed under the current project policy.
