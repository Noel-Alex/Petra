# Application shell DOX contract

## Purpose
Own React/browser orchestration around Petra's authoritative worker and presentation layers.

## Authority boundary
- React never mutates biological state directly. It issues typed worker requests and renders immutable snapshots/events.
- workerSession.ts owns browser Worker lifecycle, serialized request delivery, command correlation, pending/error state, and disposal; it does not own simulation equations or scientific interpretation.
- Keep src/sim/** and src/worker/** independent from React. Active simulation-composition work belongs to #37.
- UI control planning stays in src/ui/experimentControls.ts; app adapters execute its ControlEffect rather than duplicating replay/reset/seed semantics.
- `runtimeView.runControls` is the single presentation permission projection for Step / Reset / Replay / Seed. `ExperimentRunControls.tsx` may hold seed draft text and bounded dispatch feedback, but every effect goes through `ExperimentRuntime.dispatch()`; React never constructs worker requests or a parallel replay history. Reset preserves the active run identity/seed, Set Seed starts a fresh run through the canonical uint32 validator, and Replay consumes only runtime-accepted replayable command history.
- `experimentRuntime.ts` composes control intent, WorkerSession state, authoritative command confirmation, and timeline projection. Commands become replay history only after a returned authoritative event confirms both their command id **and the matching command event type** (`advance→advanced`, `apply-ciprofloxacin→ciprofloxacin-applied`, synthetic fixture pulse→synthetic-pulse).
- Step-local ecology observations are consumed only as companions to the newly accepted composed snapshot. `ExperimentRuntime` binds them to its current `runBranchIdentity` and clears them whenever a new accepted snapshot omits the observation or a fresh history generation clears the snapshot. UI/render consumers must not cache an observation across runtime branch generations or infer one from endpoint density.
- `ExperimentRuntimeState.runBranchIdentity` is the single app/runtime-owned command-history generation identity. It is derived from the exact `RunIdentity` plus an explicit safe-integer generation, remains stable across ordinary accepted commands/snapshots/interventions, and rotates after admitted reset, reseed, replay, or explicit checkpoint restore. `ExperimentRuntime.restoreCheckpoint(...)` is the framework-neutral restore/fork primitive: the accepted checkpoint becomes an explicit branch origin, post-origin accepted commands start a fresh replay suffix, and later Replay must execute initialize → the same checkpoint restore → that suffix rather than silently replaying from genesis. Reset/reseed clear checkpoint-origin ancestry; foreign or busy restore attempts must not rotate history identity. Renderer replay and causal narration must bind through the runtime-owned identity (for example `createRuntimeDishReplayKeyframe(...)` / `bindRuntimeCausalEventStream(...)`) rather than inventing parallel branch ids. Historical scrubbing remains inspection-only; React mount count, wall clock, snapshot ids, arrival order, and Pixi state are never branch identity authority.
- `ExperimentRuntime.dispatchAuthoritativeCommand()` accepts only already-validated protocol-v5 ciprofloxacin intervention commands, requires a healthy ready Worker, routes through the existing `WorkerSession`, and leaves the command pending until that matching authoritative event arrives. React must not construct the Worker request or pre-promote the intervention into replay/timeline state.
- `ExperimentRuntime` may own one immutable caller-supplied `ComposedSimulationConfig` for the run. Start/reset/reseed/replay must clone and resend that same configuration so lifecycle actions cannot demote a biological run to the synthetic fixture path. React does not derive or edit the config.
- Protocol v5 exposes one real biological intervention mutation, `apply-ciprofloxacin`, with exact `mg/L` and global/radial/stripe/paint geometry. App tooling must still fail closed until authoritative scenario/runtime metadata supplies the exact supported tool, units, bounds/defaults and deterministic preview→command conversion; `synthetic-pulse` is never an inoculate/antibiotic/nutrient substitute. A preview never implies acceptance, and only a returned `ciprofloxacin-applied` event may promote the command into replay/timeline history. Unsupported point/nutrient/inoculate/fungus/phage/environment tools remain preview-only/disabled until their own simulation authority exists. Region inspection remains a separate #159 authority path.
- `ciprofloxacinToolAuthority.ts` owns the fail-closed app metadata contract that can make the protocol-v5 antibiotic tool application-capable: exact parameter key/label, `mg/L`, finite bounds/default/precision, explicit `set|add` semantics, and an explicit subset of supported global/radial/stripe/paint geometry. Missing or malformed metadata keeps Apply unavailable even when the runtime is ready. Do not derive dose bounds/defaults from genotype MICs, reference-PD values, renderer state, or test fixtures merely to enable the control.
- Local-region inspection consumes only the current composed `ExperimentRuntime` snapshot/checkpoint. App-layer selection may carry normalized dish input plus exact run/checkpoint/trace identity, but scientific values come from `inspectAuthoritativeRegion()`, never renderer glyphs, overlays, camera state, or interpolation. Synthetic/missing authority and run-identity drift fail closed. Intervention placement has first ownership of dish input while active, and an inspection-only waiting surface must not fabricate a `DishRenderSnapshot` merely to permit selection.
- Scientific timeline presentation stays in src/ui/timeline.ts.
- Renderer/Pixi scene authority stays under src/render/**.
- `composedDishProjection.ts` is the only app-layer projection from a composed authoritative worker snapshot into `DishRenderSnapshot`. It copies exact dish mask, aligned per-lineage model biomass, aggregate model biomass, model-resource, and ciprofloxacin `mg/L` into renderer-owned buffers; it preserves exact biological time, uses the runtime-owned `runBranchIdentity` only as the presentation sampling domain, and uses the authoritative trace hash as snapshot identity. Before Float32 presentation narrowing, it must fail closed unless checkpoint aggregate metrics (total/per-lineage biomass, total resource, occupied cells) agree with the exact spatial source arrays and aligned lineage/genotype identities; this is a render-admission consistency gate, not a second scientific measurement path. Its current field bounds are exact in-mask observed extrema, so every projected field must explicitly declare renderer `rangeMode: "snapshot-extrema"`; do not relabel those moving extrema as a stable source-owned transfer domain. Synthetic/missing authority fails closed, off-mask scientific channels must remain zero, and renderer events stay empty until protocol events carry authoritative dish coordinates. This adapter may shape presentation data but must never become an inspector/analysis authority or infer organism kind, phenotype, resistance, physical resource units, or event positions.
- `DishViewport.tsx` may choose/display source-provided render overlays and units, but it must not derive scientific units or fabricate authoritative snapshots. Product/runtime use defaults to a neutral waiting-for-authority state when no valid `DishRenderSnapshot` exists. The renderer demo fixture is allowed only through an explicit visual-development opt-in and must remain visibly labelled visual-only; missing authority must never auto-enable it.
- `overlayLegend.ts` projects the renderer-owned overlay presentation registry into DOM text/pattern metadata while preserving the field's authoritative label, unit, minimum, and maximum. Do not create a parallel app-only overlay color/meaning table; signed net growth and source-defined uncertainty must stay semantically identical between Pixi and the legend. The legend must also expose renderer-owned range semantics: omitted/`fixed` is a fixed presentation range, while `snapshot-extrema` is a current-snapshot range whose color normalization is not temporally comparable by intensity alone. Never relabel moving observed extrema as a stable physical/source scale.
- Overlay legend accessibility uses one stable mounted `aria-live="polite"` + `aria-atomic="true"` container. Overlay changes update its visible text in place; Full-motion reveal may remount only an inner visual wrapper so animation identity never becomes live-region identity. Do not add a second hidden announcer for the same overlay change.
- `dishPresentation.ts` owns presentation selection identity for field overlays. `automatic`, explicit `none`, and a specific `field` are distinct states; never overload `null` to mean both automatic and no overlay. Explicit none survives snapshot updates. If a specifically selected field disappears, reconcile the persisted selection to automatic so a later field reappearance cannot silently resurrect stale user intent. Keep one selection authority; do not reintroduce a parallel overlay-selection module.
- Dish camera controls are presentation-only. The visible overview/reset action sends a declarative reset request into the renderer rather than storing Pixi objects in app state.
- Escape is single-consumer presentation input. Editable/already-prevented controls have first refusal without invoking dish/tool callbacks. Higher-priority shell/tool handlers that return consumed stop the event before camera reset or ancestor handling. Dish overview is the fallback presentation owner only; it must not override intervention cancellation or synthesize worker commands.
- `flagshipProvenance.ts` is presentation-only: it may attach labels/value text to the versioned flagship scenario, including the selected engineering execution profile and baseline composed parameter set, but scenario identity, evidence classes, citation keys, transfer notes, limitations, and assumptions must come from authoritative scenario records. It must never infer a parameter set from a runtime snapshot or relabel engineering model-unit records as measured science. Decisive flagship records such as the unbound resource context and reference ciprofloxacin PD parameters must not disappear merely because one has incomplete presentation provenance; expose the authoritative values/source and keep missing explicit classification visibly `needs-provenance` rather than guessing measured/derived semantics. The Sources drawer must visibly distinguish this curated flagship evidence set from the current runtime's active scenario until #37 supplies authoritative scenario identity.
- Flagship measurement uncertainty is presentation metadata from the selected scenario/source record only. Preserve source-reported statistical form exactly (for example MIC assay-step margin versus relative-fitness SD/replicate count); never convert it into a different interval, a composite confidence score, or simulation noise.
- Sources is a non-modal disclosure, not a focus trap. While requested open, unconsumed Escape on the Petra app keyboard path may close it outside editable controls; close intent restores focus to the stable Sources trigger immediately. `aria-expanded` tracks **requested visibility**, while Full-motion exit may keep the drawer mounted only for the shared `planSurfaceTransition({ action: "hide" })` presentation wall-time. An exiting drawer is `aria-hidden` + inert so focus cannot re-enter it. Reduced/Off unmount immediately; reopen/preference changes/unmount must cancel stale exit timers. Exit completion is presentation-only and may never emit simulator/scientific commands.
- Sources drawer responsive geometry is CSS authority in `sourcesDrawer.css`. Do not put `inset`, `width`, `max-height`, or other breakpoint-owned layout geometry back into React inline styles, because inline specificity defeats the narrow-screen media query. React may still project runtime motion custom properties at the app boundary.

## Runtime rules
- Do not emit the next queued request until the active request receives its expected authoritative response.
- Correlate command snapshots/errors by command id; never accept a stale/mismatched snapshot as current state.
- Initialization is complete only after a ready response.
- Worker/runtime errors must become visible/recoverable UI state, not indefinite spinners.
- `WorkerSessionState.errorCode` preserves validated typed Worker refusal identity separately from human-readable error text. The current `advance-execution-policy-refusal` code means a synchronous work budget rejected the request; UI/runtime logic must not relabel it as a biological OOD/model failure or infer error class from prose. Transport/protocol failures carry no Worker error code.
- An accepted `advance` remains one non-interruptible Worker transaction. Pause may update playback intent while that request finishes, but it does not cancel authoritative work already executing; reset/reseed/replay effects are rejected as `worker-busy` while a request is pending and may be retried after the response/error. The bounded advance policy limits the maximum synchronous request work rather than inventing mid-command partial checkpoints or silently truncating simulated time.
- Browser worker transport failures are terminal request outcomes: both `error` and `messageerror` must reach `WorkerSession`, clear active/queued work through the single failure path, retain the active command id when the failed request is a command, and leave initialization failures uncorrelated. `messageerror` uses a stable payload-free diagnostic, and every subscribed Worker event listener must be removed on teardown.
- Successfully deserialized Worker messages remain untrusted runtime data. `WorkerSession` accepts `unknown`, validates the core v5 response plus any transport-only performance extension before typed handling, and on malformed responses clears queued work through the terminal failure path while retaining correlation only from the trusted active outbound request. Never adopt a command id or diagnostics value from an unvalidated response.
- Runtime request phase and spoken product status are separate presentation channels: `runtimeView.status` / `workerPhase` may change for visible ready/pending treatment, while `statusText` in the polite runtime live region must stay stable across ordinary continuous-playback ready ↔ pending churn. Errors retain alert semantics and their explicit error text.
- A snapshot whose run identity does not match active controls is foreign state: do not render/advance it, pause playback, and require an explicit reset/reinitialization path.
- Dispose workers/listeners when the owning app/runtime is torn down.
- Worker performance profiling is opt-in through `WorkerSessionPerformanceOptions`. It may observe request/response payload estimates, request-window latency, worker-reported execution time, queued requests, authoritative event-array length, sender-side synchronous `Worker.postMessage()` handoff wall time, and the main-thread cost of cloning an accepted authoritative snapshot into session-owned state. Profiling must never alter command ordering, worker/session state, replay identity, checkpoints, or trace hashes. Browser structured-clone payload sizes are estimates of application data, not exact transport framing; `senderPostMessageCallMs` is caller-visible serialization/queueing wall time rather than end-to-end transport latency, and `mainThreadSnapshotCloneMs` is local copy cost rather than worker→main transfer cost. Compact summaries must not relabel any of these observations as link bandwidth.

## Authoritative causal narration bridge
- `CausalNarrationMount.tsx` keeps exactly one stable `CausalAnnouncementRegion` mounted in the product shell. Missing authority clears/keeps that region silent; it must never unmount/remount per event.
- `causalNarration.ts` is the app trust boundary for already-authoritative `CausalEventKind` streams. Do not classify a lifecycle event as synthetic from its name alone: composed authority may also emit generic `initialized`, `advanced`, or `restored` events, and causal narration still requires the explicit authoritative causal-stream contract.
- A supplied causal stream carries exact `RunIdentity` plus an explicit `runBranchIdentity`. The run identity must match the active runtime before any event is narrated; stale/foreign streams are ignored without advancing the cursor.
- Within one `runBranchIdentity`, causal history is append-only. The app adapter stores an exact replay-relevant identity for the already accepted prefix and rejects replacement/truncation of that prefix instead of silently continuing from the old narration cursor.
- Temporary absence of the causal stream is an explicit silent presentation state, not evidence that history reset. Preserve the accepted cursor/prefix while the stream is absent or foreign; do not run supplied-stream continuity validation against an empty placeholder. - React revision detection covers every current `CausalEventBurstItem` authority field (`sequence`, `id`, `eventKind`) across the full supplied stream, so same-length/same-frontier rewrites still re-enter validation. This presentation-side scan is deterministic and O(n) in causal-history length; replace it only when runtime authority supplies an explicit collision-resistant rolling history identity with equivalent semantics.
- The runtime authority must change `runBranchIdentity` for a fresh run/branch generation (including reset/replay/checkpoint-restore histories that restart event sequence under otherwise identical run fields). Product causal collectors should use `bindRuntimeCausalEventStream(...)` to bind already-authoritative causal items to the active runtime identity; the helper supplies identity only and never promotes timeline/render events into causal science. A branch change explicitly resets the narration cursor.
- Narration stores the planner's returned sequence + event-id cursor per active stream identity. React rerenders may clear the live-region text but must not replay already accepted events.
- #37/#42 should eventually supply this stream from the composed authoritative runtime. Until that capability exists, the default product remains correctly silent rather than adapting timeline labels, Pixi state, animation cues, or wall-clock timing.

## Recovery hardening
- `runtimeRecovery.ts` owns bounded user-facing failure categories for preset, protocol, model, runtime, and presentation failures. Raw diagnostics may remain available to tests/logging but must never be rendered directly into the expo UI.
- Product/science runtime factories that depend on scenario/preset validation must use the prevalidated runtime-factory seam (or an equivalent validate-before-construction contract). Failed validation must occur before `ExperimentRuntime` / `WorkerSession` construction so no partial authoritative run exists.
