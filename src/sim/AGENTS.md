# Simulation core DOX contract

## Purpose
`src/sim/` is Petra's authoritative deterministic simulation substrate. It owns numerical/scientific state, replay identity, stochastic streams, checkpoints, metrics/events, and mechanism coordination.

## Contracts
- No React, DOM, Pixi, animation, LLM, or network dependency may enter simulation authority.
- Never call `Math.random()` in this subtree. All stochastic behavior uses an explicit serializable Petra RNG stream or a reviewed deterministic substream derived from it.
- A checkpoint must contain enough authoritative state to continue the trajectory exactly under the same engine version.
- `scenario + parameter versions + engine version + seed + ordered commands` defines replay identity. Changing numerical update order or RNG consumption is a replay/model change.
- Numeric run seeds are canonical replay identity only when they are unsigned 32-bit integers in `[0, 0xffffffff]`, matching the RNG's actual input width. Invalid aliases must be rejected before RNG initialization; never wrap/canonicalize a visibly different seed with JavaScript bitwise coercion. Seed `0` is valid.
- Serialized RNG checkpoint state is exact replay authority: the container must be a dense four-word array, every state word must already be an integer in `[0, 0xffffffff]`, and the four-word state cannot be all zero. Restore paths reject sparse/non-array containers and malformed/fractional/out-of-range/non-finite words rather than canonicalizing them with bitwise coercion.
- Checkpoint restore is atomic: validate run identity, non-negative safe-integer tick/command counters, finite non-negative synthetic scalar state, exact tick↔simulation-time consistency, and replacement RNG state before mutating any live field or clearing events. A rejected checkpoint must leave the pre-restore snapshot byte-for-byte equivalent at the typed state level.
- Successful mutating commands are closed under those same checkpoint scalar invariants. Preflight resulting tick and command-count safe-integer bounds plus finite/non-negative synthetic scalar results before consuming RNG, appending events, or mutating live state; a refused command must leave the authoritative snapshot unchanged. `advanceExecutionPolicy.ts` separately owns the versioned caller/runtime work ceiling for one synchronous `advance`: both synthetic and composed engines refuse over-budget work before RNG/state/event mutation, and accepted commands retain identical scientific/replay semantics. This execution policy is runtime safety metadata, not biology or checkpoint identity; callers that deliberately need a larger offline chunk must supply an explicit validated policy rather than bypassing the guard.
- Renderer sampling must not consume the biological RNG stream.
- Synthetic fixture state may exercise infrastructure but must be named as synthetic and removed/replaced as real mechanisms arrive; never present it as biology.
- Protocol/state changes require deterministic tests and coordination because they are high-conflict integration surfaces.
- `replayCompatibility.ts` is the single release compatibility authority for serialized checkpoints/replay artifacts. Current policy is exact-match-only: current engine/protocol, exact authority kind, scenario ID/version, parameter-set ID/version/binding, and seed. No migration is registered. Restore/replay paths must run this gate before mutating state or instantiating an engine from a self-contained artifact. See `REPLAY_COMPATIBILITY.md`.
- `experimentBundle.ts` owns the versioned compact experiment interchange: exact run identity + authority, one authoritative origin checkpoint, exact composed config when required, and ordered post-origin mutating commands. Events/metrics/source IDs are supplemental evidence only. V2 adds the exact composed `apply-ciprofloxacin` replay mutation and its intervention-bearing evidence event while continuing to exclude renderer state, raw datasets, and counterfactual ancestry; unknown fields fail closed. Counterfactual ancestry remains intentionally OFF in experiment bundle v2 even after #438 makes the dedicated counterfactual replay bundle independently verifiable; adding ancestry to general experiment interchange requires a separately versioned contract. See `EXPERIMENT_BUNDLE.md`.
- Timeline-worthy protocol events carry exact authoritative `simulationTimeHours` at emission. That timestamp is replay/wire identity and must not be reconstructed later from a newer checkpoint.
- `SimulationCheckpoint.commandCount` is the authoritative accepted mutating-command position already carried by the current versioned worker protocol. Renderer replay may project it as branch-local keyframe order, but it remains distinct from biological time. Restore/reset/replay histories that restart or regress this count are new history scopes and must not be concatenated under one renderer branch identity.
- Required worker wire-shape changes bump `PROTOCOL_VERSION`; do not silently extend an existing protocol version with new required fields.
- Protocol-v7 Worker errors may carry the optional validated `advance-execution-policy-refusal` code so orchestration can distinguish a runtime work-budget refusal from model/numerical failure without parsing message text. The code is diagnostic transport metadata only and never enters checkpoints, trace hashes, or biological state.
- Successfully deserialized Worker payloads are still untrusted runtime data. `protocolRuntime.ts` is the single framework-neutral promotion boundary for the protocol-v7 core envelope and nested structural/replay-critical identity/checkpoint/snapshot state. It preserves validated original payloads so current composed fields are not silently dropped. Transport promotion does **not** replace canonical scientific validation (`validateComposedStateAgainstConfig`, engine restore invariants, parameter-set binding); malformed requests never reach an engine and malformed responses never become authoritative snapshots.
- Worker protocol v7 distinguishes infrastructure-only synthetic checkpoints from `authority: 'composed'` checkpoints. `ComposedSimulationEngine` is the worker-facing deterministic loop over `authoritative.ts`; it advances resource/biomass ecology, preserves ordered lineage/genotype identity, validates checkpoint aggregates before restore, and rejects synthetic fixture commands. Omitted `composedConfig` remains a narrow infrastructure/test path only and therefore requires a `RunIdentity` with no `parameterSetBinding`; synthetic checkpoints carrying a composed binding are invalid. Composed runs require both a composed config and its validated parameter-set binding.
- `counterfactual.ts` owns deterministic fork authority over the current engine contract: one exact checkpoint is deep-cloned into both branches, branch metadata stays outside biology/RNG state, and replay bundles contain the exact fork checkpoint plus ordered post-fork command payloads. Restore/snapshot commands are not legal branch-history mutations. See `COUNTERFACTUAL.md`.
- `snapshotTrace.ts` is the single snapshot trace serialization/hash authority for both synthetic and composed snapshots. Engines must not carry private copies of the stable-stringify/FNV algorithm. Counterfactual replay bundle v2 retains exact parent events so ancestry trace identity is independently recomputable; a trace mismatch is provenance failure, not checkpoint repair. The hash is deterministic regression identity, not cryptographic authenticity.
- `authoritative.ts` is a bounded composition scaffold over merged mechanism kernels. It accepts only caller-supplied configuration/state, carries a canonical configuration fingerprint so lineage ordering/mechanism configuration cannot drift silently between steps, and is not itself the browser worker protocol or a substitute for versioned run identity/provenance. `validateComposedStateAgainstConfig()` is the single authority for scientific composed-state/config invariants shared by direct continuation and checkpoint restore; engine-only run identity, tick/time, command-count, event, and aggregate-metric checks remain separate runtime/transport validation.
- `parameterSetBinding.ts` owns the bridge from human-readable parameter-set ID/version to the exact composed configuration fingerprint. Product/provenance bindings must come from versioned provenance/scenario data; they must never be generated by fingerprinting an arbitrary caller config during initialization. Ad-hoc tests use the explicit `fixture:` namespace and fixture helper. The binding lives in run identity so checkpoint, replay, trace, and downstream metadata can preserve it.
- `flagshipComposition.ts` is the product-facing scenario→config trust boundary for the bundled flagship. It may generate a provenance binding only from the repository-owned versioned `composedParameterSet` plus its referenced execution/resource/loss/geometry records. Callers may supply seed and initial state (model-resource level + founder placements), but may not inject mechanism values or an alternate scenario into this binding path.
- `releaseScientificIdentity.ts` owns the preparatory #561 release record over current flagship authority. It must bind the exact current run/provenance/replay identities plus the canonical **accepted** initial run state; raw resource/biomass literals, duplicate inocula, or caller ordering must not create distinct release identities when Float32 storage and cohort accumulation produce the same authoritative state. See `RELEASE_SCIENTIFIC_IDENTITY.md`.
- Configured founder definitions are static run configuration; runtime biological lineage identity is replay-critical checkpoint state. Founder config IDs never become runtime lineage IDs directly: `LineageRegistry` allocates deterministic `L1/L2/...` IDs in founder order, and the composed state checkpoints ordered runtime lineage IDs, genotype IDs, persisted baseline non-drug loss, and the full lineage-registry allocator/ancestry/event checkpoint. Runtime child creation order therefore changes replay identity without changing the static composed configuration fingerprint.
- `taxonIdentity.ts` owns the framework-neutral biological identity contract needed before mixed-species composition. A versioned source-backed taxon registry is separate from renderer presentation metadata, and the runtime lineage→taxon map is ordered exactly with authoritative lineage channels. Dynamic extensions are append-only: prior lineage→taxon assignments cannot be rewritten when child lineages are created. `microbialGroup` is only a coarse biological compatibility category; it never authorizes rod/coccus/yeast/hyphal morphology or any renderer primitive. Protocol/checkpoint integration must preserve this separation when #877 moves beyond the standalone contract.
- Relative fitness is resolved only from the curated evolution graph against the **runtime** state genotype order. Baseline non-drug loss for runtime-created children comes only from explicit versioned `dynamicLineageLossPolicy`; explicit `null` keeps child activation fail-closed. Ciprofloxacin MIC/PD authority must cover every runtime genotype before stepping under drug exposure.
- Runtime lineage IDs/genotype IDs and evolution scenario ID/version are canonical replay identity: they must be non-empty strings with no surrounding whitespace. Serialized lineage identity/parameter/biomass channels must align one-to-one with the lineage registry creation order, and restore/promotion must fail closed on malformed containers, registry/channel drift, or unknown genotype identity.
- Composed sampling execution policy is replay-critical numerical configuration, not biology. Every composed config must supply either an explicit validated `SamplingExecutionPolicy` or explicit `null`; omission is rejected rather than aliased to null. The canonical `samplingExecutionPolicyIdentity(...)` string (or null) participates in the configuration fingerprint, so changing exact/accelerated execution policy cannot silently continue an old composed state.
- Protocol v7 / composed-state v5 retain ciprofloxacin concentration as mutable checkpoint authority. `ComposedSimulationConfig.ciprofloxacinConcentrationMgPerL` is the fingerprinted **initial** landscape, while `ComposedSimulationState.ciprofloxacinConcentrationMgPerL` is the current replay-critical landscape. Non-zero current exposure requires the supported source-backed PD/MIC authority, concentration is finite/non-negative, canonical Float32, and exactly zero off-mask. `stepComposedState` derives per-genotype spatial loss only through `composeSpatialCiprofloxacinLoss(...)`; it must not duplicate the PD equation or infer MICs from names. `apply-ciprofloxacin` is the bounded typed mutation path for exact `mg/L` global/radial/stripe/paint geometry with `set|add` semantics. Accepted intervention commands increment `commandCount` and emit `ciprofloxacin-applied` at the current biological time without advancing ticks; rejected commands are replay no-ops. This authority edits concentration landscapes only—it does not claim calibrated diffusion, decay, clearance, or physical transport.
- The currently supported composed ecology runtime uses one replay-critical fixed biological interval, `hoursPerTick`; Petra does not add a global adaptive clock merely because the scientific target architecture permits one. Numerical stability remains mechanism-owned inside that interval: explicit 2-D field diffusion subdivides deterministically to `alpha <= 1/4` and refuses non-representable substep plans before mutation, ecology refuses `spreadRate * hoursPerTick > 0.25`, and finite first-order loss uses exact exponential survival. Future integrated stochastic event/tau-leap mechanisms must add a deterministic, versioned probability/substep policy to replay identity before they may require tick adaptation.
- The composed-state dish mask is an authoritative domain boundary: resource, ciprofloxacin concentration, and lineage biomass must be exactly zero where `mask === 0` in both initial configuration and any restored/mutated state. Validation fails closed rather than clamping caller-supplied science, and aggregate resource/lineage metrics sum only in-mask cells.
- `populationAuthority.ts` owns the reviewed shared continuous-biomass → discrete standing-host/division-opportunity conversion under an explicit cell-equivalent calibration and versioned numerical policy. Its configuration identity covers only static grid/mask + calibration/policy authority; ordered lineage membership is replay-critical checkpoint state and may grow only through the append-only `extendDiscretePopulationAuthorityLineages(...)` boundary, which preserves existing division residuals and gives newly created channels zero prior division supply. Protocol v7 / composed-state v5 enable this authority inside composed execution **only** when `populationAuthority` is an explicit validated config; explicit `null` is the required no-calibration state. Enabled static configuration identity joins the composed fingerprint, and standing counts plus standing/division residuals are checkpointed and validated against exact committed lineage biomass on continuation/restore. `stepComposedStateDetailed(...)` advances this authority from the ecology kernel's per-lineage/per-cell division-flux ledger and returns safe-integer spatial division opportunities; the existing `stepComposedState(...)` remains a metrics-only wrapper. The bundled flagship stays `null` because no scenario-owned biomass↔cell-equivalent calibration exists. Downstream mutation/phage composition must consume these integer outputs rather than independently rounding continuous biomass.
- `metrics.ts` owns the versioned renderer-independent authoritative metric projection and deterministic tick-based sampling cadence. Metric samples carry exact run identity + biological time, aggregate lineage/genotype fractions from composed checkpoint authority, and compute resistance only from an explicit caller-supplied genotype set; never infer resistance from names/colors or chart state. Sampling cadence is expressed in authoritative ticks, not render frames or wall-clock animation cadence. Selected local metric summaries must be projected from `regionInspector.ts` output rather than re-reading renderer state or reimplementing spatial selection; they share the same tick cadence, preserve exact run/config/command-position identity and model units, validate lineage/genotype biomass coherence, and keep `no-grid-coverage` distinct from a measured zero.
- `composedObservationTransaction.ts` owns the versioned identity/validation contract for derived step-local observations that must remain attached to one exact accepted composed-state position. The record binds run/config identity, tick, biological time, accepted command position, exact grid/mask, and ordered lineage/genotype identity, but is **not** checkpoint continuation authority and constructing one after the fact does not prove an observation was produced by that state. Engine/runtime wiring must create and attach it atomically with the derived observation; consumers fail closed on cross-position mixing.
- `composedEcologyObservation.ts` owns the pre-wire payload envelope for one `EcologyFluxObservation` plus one exact `ComposedStepObservationPosition`. It enforces matching grid/mask/ordered lineage identity, composed-owned `model-biomass` / `hour` semantics, finite positive executed duration, detached payload arrays, and a non-negative derived observation interval. This envelope is structural preparation only: it still does not prove causal provenance unless the engine constructs it atomically from the accepted ecology step, and it deliberately does not own app/runtime `runBranchIdentity` or the final Worker snapshot wire field.
- Accepted composed `advance` snapshots may carry one optional ecology-observation envelope produced atomically from the final executed ecology step of that command. Zero-tick advance, snapshot-only, intervention-only, initialize, and restore snapshots must omit it so stale step evidence cannot masquerade as current. The optional envelope is validated at protocol promotion but remains excluded from checkpoint continuation and snapshot trace identity; changing its payload cannot change replay/biology authority.
- `regionInspector.ts` is the authoritative read-only local-region projection boundary. Selection geometry is normalized and presentation-independent; values are aggregated directly from a composed simulation checkpoint, never Pixi/render snapshots. Every inspection preserves a cloned exact `RunIdentity`, authoritative tick, `simulationTimeHours`, and accepted command position from that same checkpoint; consumers must never reconstruct biological time from render cadence, animation time, or a later snapshot. The checkpoint parameter-set binding must match the composed-state configuration fingerprint before any readout is published. Every lineage row carries the exact aligned composed-state `genotypeId`; lineage/genotype/channel length drift fails closed, and downstream consumers must not infer phenotype or resistance semantics from the identifier alone. A selection covering zero authoritative in-mask grid-cell centres returns the typed `no-grid-coverage` outcome with no biomass/resource measurement fields while retaining the same run/time identity; this is distinct from a covered region whose measured values are genuinely zero. Current composed-state biomass/resource units remain explicit model units; UI must not relabel them as cells, concentration, mass, or area density without a provenance-owned physical unit bridge.
- Any enabled phage spatial-unit bridge is replay-critical configuration. Its canonical identity (biomass↔cell-equivalent scale, interaction volume, grid pitch, and evidence classifications/source keys) must be included in authoritative scenario/configuration fingerprinting before phage dynamics can participate in checkpoints.

## Verification
At minimum, test identical-seed/command replay, RNG state round-trip, checkpoint continuation, invalid cross-run restore, and validation of command bounds. Scientific mechanisms add their own invariants/fixtures.

### Composed command atomicity

- Treat every mutating composed command as one replay transaction. Run multi-tick `advance` work and `apply-ciprofloxacin` field mutation on detached state and publish only after the full command validates/succeeds.
- A rejected composed command must leave checkpoint state (including ciprofloxacin), metrics, tick, command count, and event history unchanged. Do not expose a partially advanced or partially painted biological state after a numerical/model refusal.

- `scienceModeAdmission.ts` is the fail-closed authority for whether a scenario may be presented as grounded Science Mode. Parseable/runnable presets are not admission evidence. Missing validation, provenance, primary-source resolution, transfer disclosure, visible limitations, UNBOUND required values, or engineering-only execution authority keeps a scenario experimental; engineering model-unit profiles never satisfy physical calibration claims.
- `parameterCompatibility.ts` owns the framework-neutral fail-closed compatibility gate for composing individually sourced parameter records. Required organism/background, medium/substrate, temperature, pH, oxygen, assay, and model context must match exactly unless a known mismatch is covered by an explicit versioned field-scoped transfer/calibration decision with a visible limitation; missing context is never transferable, and the gate never averages or numerically reconciles conflicts. Its canonical compatibility-decision identity must be bound into scenario/composed configuration identity before production composition may rely on such decisions.

## Flagship intervention control projection
- `flagshipInterventionControl.ts` projects the bundled scenario's versioned ciprofloxacin product-control metadata into immutable command-guardrail data. It validates source-range/provenance consistency and must fail closed on missing, malformed, widened, or unsupported control metadata.
- This projection is not checkpoint biology and does not change the protocol command vocabulary. Product code may consume its exact `mg/L` bounds/default/geometry/blend contract, but must not derive a wider range from genotype MICs, renderer state, or demo values.
